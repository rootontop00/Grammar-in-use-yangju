# 인수인계: 영어 알파벳 쓰기 앱 (한글 획순 공책의 영어판)

이 문서는 새 대화창에서 영어판 작업을 바로 시작할 수 있도록 정리한 것이에요.
지금까지 만든 **한글 획순 공책**(`hangul/`)과 같은 방식으로, 예비 초등학생이 태블릿에서 손가락이나 펜으로 **영어 알파벳 획순과 획 방향**을 연습하는 앱을 `english/`에 만드는 것이 목표예요.

---

## 0. 새 대화에서 처음 할 일

1. 이 문서를 끝까지 읽어요.
2. `hangul/index.html`을 훑어봐요. 하나의 파일에 앱 전체가 들어 있고, 영어판도 이 파일을 복사해서 시작하는 것을 추천해요(4장 참고).
3. 아래 **"먼저 정할 것"**은 추천안대로 진행해도 돼요. 사용자에게는 꼭 필요한 것만 짧게 물어봐요.
4. 첫 결과물은 대문자·소문자 일부만 넣은 작은 버전으로 빨리 보여 주고, 사용자 피드백을 받아서 늘려요. 한글판도 이렇게 키웠어요(2장 참고).

### 먼저 정할 것 (추천안)

| 정할 것 | 추천안 | 이유 |
|---|---|---|
| 글씨체 | 초등 영어 교과서식 **활자체(ball-and-stick)** | 입학 후 학교에서 배우는 모양. 필기체는 제외 |
| 쓰기 칸 | **영어 4선 공책** (1선 위, 2선 점선, 3선 빨간 기준선, 4선 아래) | 아이가 학교에서 쓰게 될 공책과 같음 |
| 범위 | 대문자 26 → 소문자 26 → 헷갈리는 글자 → 쉬운 낱말 → 이름 → 짧은 문장 | 한글판과 같은 단계 흐름 |
| 화면 글꼴 | 글자 보여 주기는 **Andika**(Google Fonts), 버튼은 한글판처럼 Jua | Andika는 아이들이 배우는 a, g(한 고리 모양)로 보여 줌 |
| 위치 | `english/` 폴더, 주소 `https://rootontop00.github.io/Grammar-in-use-yangju/english/` | 한글판과 나란히 |
| 설명 문구 | 한국어 (아이와 부모가 한국어 사용) | 글자 이름은 영어 음성 + 한글 발음 표기(에이, 비, 씨…) |

## 1. 사용자와 아이

- 사용자는 아이의 부모예요. 아이는 **예비 초등학생(내년 입학)**이에요.
- 한글은 다 알지만 **획순이 틀려서** 한글판을 만들었어요. 영어도 같은 목적이에요.
- 사용자는 **실제 태블릿**에서 아이와 써 보고 피드백을 줘요. 기종(아이패드인지 갤럭시탭인지)은 아직 확인하지 못했어요.
- 소통은 한국어로 해요. 요청은 짧아요("만들어봐", "링크", "다운로드 못해?", "앱처럼 쓰려면?").
  - 답도 짧고 쉽게 해요. 사용자가 할 일은 단계별로 분명하게 알려 줘요.
- 기술 용어보다 "무엇이 달라졌는지", "지금 사용자가 할 일"을 먼저 말해요.

## 2. 지금까지의 흐름 (한글판에서 배운 것)

사용자의 요청 순서예요. 영어판은 **처음부터 마지막 상태**로 만들면 돼요.

1. **"획순 연습 만들어봐"**
   - 보기 → 따라 쓰기 → 혼자 쓰기, 순서·방향 판정, 별, 스티커를 넣은 첫 버전.
2. **"틀리면 바로 앱이 꺼짐"** (태블릿)
   - 원인(추정): 틀릴 때 효과음(WebAudio)이 나는 동안 음성(speechSynthesis)을 바로 시작함.
   - 해결: 음성은 **버튼을 누를 때만** 말하고, 효과음과 겹치지 않게 함. 6장의 규칙을 반드시 지켜요.
3. **"다운로드 못해?"**
   - 파일 하나(`한글획순공책.html`)로 받을 수 있게 함.
4. **"샘플이 적어. 반복, 훨씬 많은 경우, 단계로 성취감"**
   - 한 글자 3번 쓰기, 62단계 지도, 장마다 시험·메달, 복습, 오늘 목표, 레벨, 스티커.
   - 자유 연습: 음절표, 글자 만들기, 낱말 147개, 문장, 이름.
5. **"앱처럼 쓰려면?"**
   - 홈 화면 설치(manifest, 아이콘, 서비스 워커 오프라인)와 GitHub Pages 배포.
6. **"틀리거나 중간에 그만하면 거기부터"**
   - 획 하나마다 저장하고, '하던 곳부터' 이어 하기.
   - 단계를 마치면 '틀린 글자만 다시 쓰기' 버튼.

## 3. 한글판 코드 구조 (`hangul/index.html`, 약 1,900줄)

외부 스크립트 없이 HTML·CSS·JS가 파일 하나에 다 들어 있어요. 글꼴만 Google Fonts에서 불러요. 대략 이런 순서예요.

| 구역 | 내용 | 영어판에서 |
|---|---|---|
| CSS 토큰 | 밝은 테마 = 쓰기 공책, 어두운 테마 = 칠판. 획 색 `--s1..--s8`, 역할 색 `--r-cho/jung/jong` | 그대로 사용. 역할 색은 대문자/소문자 등으로 바꾸거나 빼기 |
| storage | `STORE_KEY = 'hangul-stroke-notebook:v1'`, `store` = 별, 단계, 복습(weak), 날짜별 쓴 수, 메달, 설정, `resume` | **키를 바꿔요** (`english-stroke-notebook:v1`) |
| geometry | `resample`, `partial`, `toD`, `bbox`, 작은 경로 언어 `parsePath` (`M x y`, `L x y`, `Q cx cy x y`, `O cx cy rx ry`) | 그대로 사용 + 원/호 명령 확장(4장) |
| letter data | `J` = 자모마다 **쓰는 순서대로** 획 목록. 획은 0–100 상자 안의 경로이고, 경로 방향이 곧 획 방향 | **알파벳 획 데이터로 교체** |
| building | 자모를 글자 상자에 배치(`layout`, `placeConsonant`, `syllableStrokes`), `makeUnit` | 한글 조합 대신 4선 위에 글자 높이(대문자, x-height, 위/아래로 긴 글자)대로 배치 |
| content | `CHAPTERS`(장·단계), 자유 연습 목록, `LEVELS`, `STICKERS` | 내용만 교체 |
| sound & voice | WebAudio 효과음, `say()` / `hush()` | 그대로 + `lang='en-US'` |
| session | `startSession` → `beginItem` → `startRound` → 획 판정 → `unitDone` → `roundDone` → `itemDone` → `finalizeSession` → `showWin` | 그대로 사용 |
| resume | `saveResume()`는 획·라운드·글자마다 저장, `resumeSession()` | 그대로 사용 |
| judging | `follow`, `matchStroke`, `judge` (아래 설명) | 그대로 + 점 획 처리(4장) |
| board drawing | 레이어 `gl`(흐린 안내선), `done`, `hint`(빛나는 경로·번호·화살표), `anim`, `badges`, `ink` | 칸 그리기만 4선으로 교체 |
| home / free | 단계 지도(`renderRoad`), 단계 시트, 자유 연습 탭 | 탭 내용만 교체 |

### 획 판정 방식 (그대로 쓰면 돼요)

- 아이가 그은 선과 목표 획을 둘 다 1.5 단위 간격으로 다시 샘플링해요.
- `follow()`는 목표 경로를 **앞으로만** 따라가며 얼마나 덮었는지 봐요. 그래서 반대 방향이나 반대로 도는 원은 실패해요.
- 판정 결과는 이렇게 나뉘어요.
  - `ok`: 정답
  - `order`: 다른 획을 먼저 씀
  - `reverse`: 방향이 반대
  - `toolong`: 다음 획까지 한 번에 이어서 씀
  - `short`: 중간에 뗌
  - `start`: 시작점이 다름
  - `again`: 이미 쓴 획
  - `miss`: 그 밖
- 허용 오차
  - 큰 글자: `TOL_J = { tol: 11, startTol: 15, endTol: 15, short: 16, win: 15 }`
  - 작은 글자: `TOL_S = { tol: 8.5, startTol: 11.5, endTol: 11.5, short: 12, win: 12 }`
- 고친 버그들
  - 덮은 정도를 비율로 계산하면 짧은 획이 실패했어요. 그래서 **남은 길이(절대값)** ≤ max(18%, 6)로 바꿨어요.
  - 아주 짧은 획(길이 7 미만, ㅎ·ㅊ의 꼭지)은 방향을 보지 않아요. 짧게 콕 찍어도 인정해요.

## 4. 영어판 설계 제안

### 4선 쓰기 칸과 좌표

- 0–100 상자에 가로선 4개를 그어요. 예: 1선 y=12, 2선 y=38(점선), 3선 y=64(빨간 기준선), 4선 y=90.
- 글자 높이
  - 대문자: 1선 → 3선
  - x-height 소문자(a c e m n o r s u v w x z): 2선 → 3선
  - 위로 긴 글자(b d f h k l t): 1선 → 3선
  - 아래로 긴 글자(g j p q y): 2선 → 4선
- 글자마다 폭이 달라요(i는 좁고 m·w는 넓음). 한 글자 연습은 정사각형 칸 그대로, 낱말은 글자 하나씩 연습하면서 위에 낱말 전체를 보여 줘요. 한글판의 낱말 처리와 같아요.
- 나중에 "낱말을 한 줄에 이어 쓰기"(넓은 칸)를 2단계로 고려해요.

### 원과 호: 경로 언어 확장이 필요해요

- 한글 `O` 명령은 "맨 위에서 시작해 왼쪽으로(시계 반대) 한 바퀴"만 돼요.
- 영어는 시작 위치가 달라요.
  - a c d g o q: 대개 1~2시 방향에서 시계 반대 방향으로 시작해요.
  - b p: 세로선에서 시계 방향으로 볼록하게 그려요.
- 그래서 `A cx cy rx ry 시작각 회전각` 같은 호 명령을 추가해요. 회전각의 부호로 방향을 정해요.
- 반대 방향 판정은 `follow()`가 경로 방향으로 해 주니, 경로만 맞게 만들면 돼요.

### 점 획 (i, j, 문장 부호)

- 지금 판정은 길이 2.5 미만의 선을 '콕 누름'으로 보고 무시해요.
- 점 획에는 `dot` 종류를 만들어서, 목표 점 반경 안을 누르면 정답으로 처리해요.
- 점 획은 화살표 대신 반짝이는 점만 보여 줘요.

### 획순 초안 (꼭 확인 필요)

아래는 흔히 가르치는 활자체 순서를 정리한 **초안**이에요. 교재마다 조금씩 달라요. 만들기 전에 초등 영어 교과서나 Zaner-Bloser 같은 자료로 확인하고, 사용자에게 보여 주고 확정해요.

- **대문자**
  - A: ／ ＼ —
  - B: | 다음 위·아래 볼록(1~2획)
  - C: 오른쪽 위에서 시계 반대로
  - D: | 다음 볼록
  - E: | — — —
  - F: | — —
  - G: C처럼 돈 다음 —
  - H: | | —
  - I: |
  - J: 내려오다 왼쪽으로 갈고리
  - K: | 다음 ／ 다음 ＼(또는 < 한 획)
  - L: | — (꺾어 한 획)
  - M: | ＼ ／ |
  - N: | ＼ |
  - O: 위에서 시계 반대로
  - P: | 볼록
  - Q: O 다음 꼬리
  - R: | 볼록 다리
  - S: 위에서 한 획
  - T: | — 또는 — |(**교재마다 다름, 확인**)
  - U: 한 획
  - V: ＼ ／
  - W: ＼／＼／
  - X: ＼ ／
  - Y: ＼ ／ |(또는 ＼ 긴 ／)
  - Z: — ／ —(한 획)
- **소문자**
  - a: c처럼 돈 다음 |
  - b: 긴 | 다음 볼록
  - c: 한 획
  - d: c처럼 돈 다음 긴 |
  - e: — 다음 c
  - f: 위 갈고리 다음 —
  - g: c 다음 | 아래 갈고리
  - h: 긴 | 다음 아치
  - i: | 다음 점
  - j: 갈고리 다음 점
  - k: 긴 | 다음 <
  - l: 긴 |
  - m: | 아치 아치
  - n: | 아치
  - o: 시계 반대로
  - p: 긴 | 다음 볼록
  - q: c 다음 긴 |
  - r: | 작은 아치
  - s: 한 획
  - t: | 다음 —
  - u: 한 획 다음 |
  - v: ＼ ／
  - w: ＼／＼／
  - x: ＼ ／
  - y: ＼ 긴 ／
  - z: — ／ —
- **b/d/p/q 헷갈림**
  - d는 "동그라미 먼저, 막대 나중", b는 "막대 먼저, 동그라미 나중"이에요.
  - 획순 판정이 바로 이 차이를 잡아 줘서 가장 효과가 큰 부분이에요. 헷갈리는 글자 단계를 꼭 넣어요.

### 단계 지도 초안

1. 대문자 직선: E F H I L T
2. 대문자 사선: A K M N V W X Y Z
3. 대문자 곡선: B C D G J O P Q R S U → 대문자 시험
4. 소문자 묶음: l i t / c o a d g q / n m h r / b p / u y v w / e f j k s x z → 소문자 시험
5. 헷갈리는 글자: b d p q, m n u h, 대문자·소문자 짝(Aa Bb…)
6. 쉬운 낱말: cat dog sun pig bed cup…(파닉스 CVC), I a the is you my…(사이트 워드)
7. 이름(영문 이름 입력), 짧은 문장: I love you / Hi Mom(문장 부호는 점 획 처리 후)

자유 연습에는 알파벳표(A–Z, a–z), 주제별 낱말, 직접 입력, 섞어서 5개를 넣어요.

### 그대로 가져올 것

- 한 글자 3번 쓰기(따라 쓰기 → 흐린 글씨 → 혼자 쓰기), 낱말 2번, 문장 1번
- 별 계산(따라 쓰기 이후 실수 0 → 3개, 1~2 → 2개, 그 이상 → 1개), 누적 별, 레벨, 스티커(별 12개마다), 메달
- 복습(틀린 글자 모음), 단계 끝 "틀린 글자만 다시 쓰기"
- 이어 하기(획마다 저장), 오늘 목표와 7일 기록
- 홈 화면 설치(manifest, 아이콘, `sw.js`)
  - 캐시 이름과 저장 키는 **영어판 전용**으로 바꿔요.
  - `english/sw.js`의 범위는 `english/` 폴더로 따로 잡혀요.

| `extract-fragment.sh hangul/index.html 조각.html` | 배포용 파일 → 아티팩트용 조각. 위 스크립트와 왕복하면 같은 파일이 나와요 |
| `make-icons.js` | 앱의 실제 획 데이터로 홈 화면 아이콘(512/192/180) 만들기 |
| `test-hangul-flows.js` | 모든 글자의 모든 획(1,763개)을 어긋나게 따라 써서 정답 인정, 거꾸로는 거부를 확인하고 단계·복습·시험·자유 연습을 끝까지 진행 |
| `test-hangul-resume.js` | 틀린 직후 새로고침, 낱말 중간에 뒤로 가기, 축하 화면 중 종료 후 이어 하기 확인 |
| `test-pwa-offline.js` | 로컬 서버에서 설치 가능 여부, 오프라인으로 열기 확인 |

실행 방법 (Playwright와 Chromium은 클라우드 환경에 이미 있어요)

```sh
export NODE_PATH=$(npm root -g)
node tools/test-hangul-flows.js hangul/index.html [스크린샷폴더]
node tools/test-hangul-resume.js hangul/index.html
python3 -m http.server 8765 --bind 127.0.0.1 & SERVER=$!
node tools/test-pwa-offline.js http://localhost:8765/hangul/ ; kill $SERVER
```

- 테스트 스크립트는 페이지 끝의 `syncSound(); syncSettings(); renderHome();\n})();` 줄 뒤에 `window.__d = {...}`를 끼워서 내부 함수를 꺼내 써요. 영어판도 같은 마지막 줄을 유지하면 그대로 고쳐 쓰기 쉬워요.
- **가장 중요한 테스트는 "모든 획 판정"이에요.** 글자 데이터를 바꿀 때마다 돌려요.

## 6. 꼭 지킬 것 (한글판에서 겪은 문제)

- **음성 규칙 (앱 꺼짐 방지)**
  - `speechSynthesis`는 **아이가 버튼을 누른 직후에만** 써요.
  - 효과음이 나는 중(마지막 효과음 끝 + 150ms 전)에는 말하지 않아요.
  - `cancel()` 직후 바로 `speak()`하지 않아요.
  - 목소리 객체를 억지로 지정하지 않아요(`lang`만 지정).
  - 틀렸을 때, 칭찬할 때, 숫자 세기에는 음성을 쓰지 않아요.
- **좁은 화면**
  - 그리드 안에 표나 긴 내용이 있으면 열을 `minmax(0, 1fr)`로 잡아요. 그렇지 않으면 휴대폰에서 화면이 옆으로 밀려요.
  - 긴 문장의 글자 줄은 낱말 단위로 줄바꿈해요.
- **저장소**
  - `localStorage`는 기기·브라우저마다 따로예요.
  - 아이패드는 홈 화면 앱과 Safari가 기록을 따로 가져요. 사용자에게 "처음부터 홈 화면 아이콘으로 열기"를 안내해요.
- **배포 후 404**
  - merge 전에는 Pages 주소가 404예요.
  - 방금 404를 본 브라우저는 몇 분 동안 그 화면을 기억할 수 있어요.
- **결과 저장 순서**: 단계 결과는 축하 화면 **전에** 저장해요. 축하 중에 앱이 꺼져도 통과가 남아요.
- **Git**
  - 세션이 지정한 브랜치에서 작업해요.
  - 커밋·PR에 모델 이름을 넣지 않아요.
  - 루트 `index.html`(영어 듣기 페이지)은 건드리지 않아요.
